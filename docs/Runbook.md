# MLOps 模型监控与异常处置 Runbook

## 1. 适用范围

本 Runbook 用于指导 `quant_qlib_mlops` 项目在日常运行过程中，出现数据质量异常、特征分布漂移或模型预测效果下降时的排查与处置。

项目目前采用本地 WSL2 环境运行日更数据流水线、模型训练、批量推理和监控服务。模型评估以历史回测和样本外预测结果为依据，不涉及真实资金交易和自动化交易执行。

## 2. 异常触发条件

### 2.1 数据质量异常

- 数据下载失败、行情日期滞后或 CSV 数据缺失。
- OHLC 价格关系异常、非正价格、无效成交量等质量检查未通过。
- 日更流水线出现 `COMPLETED_ISSUES` 或其他异常状态。

### 2.2 特征分布漂移（PSI）

- 核心特征 PSI 连续 2 个交易日超过 0.25。
- Grafana 监控面板出现 PSI 异常或 Webhook 告警。

PSI 超过阈值表示特征分布可能发生变化，需要结合数据质量、市场环境及其他监控指标进一步判断，不能单独作为模型失效的依据。

### 2.3 模型预测效果下降（IC）

- 已成熟预测日期的滚动 Rank IC 持续为负。
- 滚动 IC 或 Rank IC 明显低于历史评估水平。
- 多个连续评估窗口均表现出预测能力下降。

IC 计算必须基于已经获得真实收益反馈的成熟预测日期，避免将尚未成熟的预测结果纳入评估。

## 3. 应急处置流程（SOP）

### Phase 1：异常确认（T+0）

1. 检查日更流水线执行日志，确认数据下载、数据质量检查、特征生成及后续处理是否正常完成。
2. 登录 Grafana，查看 PSI Top 10、IC 和 Rank IC 监控面板。
3. 检查异常日期对应的原始行情 CSV，确认是否存在缺失、价格异常或数据源问题。
4. 判断异常属于数据问题、特征分布变化，还是模型预测效果下降。

如果数据质量检查未通过，应优先处理数据问题，不应直接将异常归因于模型失效。

在确认模型预测效果持续下降之前，暂停将当前模型输出作为有效预测信号使用，并保留相关日志和监控记录。

### Phase 2：观察与排查（T+1 至 T+3）

1. 持续观察 PSI、IC 和 Rank IC 的变化。
2. 检查 yfinance 数据源是否出现限流、行情缺失或异常价格。
3. 排查是否存在市场剧烈波动、交易制度变化或其他可能影响特征分布的因素。
4. 正常执行 `scripts/m5_run_daily_pipeline.sh`，更新行情、特征及监控数据。
5. 暂不因单日异常直接启动模型重训。

观察期间应区分短期数据异常和持续性市场分布变化，避免因短期噪声频繁调整模型。

### Phase 3：模型重新评估与训练（必要时）

如果确认模型预测效果持续下降，且数据质量和处理链路正常，可启动人工评估与重新训练流程。

1. 检查当前模型的训练数据范围、特征集和 Walk-forward 评估结果。
2. 根据实际数据情况，重新设计训练窗口和样本外测试窗口。
3. 使用现有训练流程执行模型训练及 Walk-forward 验证。
4. 对比新旧模型在不同评估窗口中的 IC、Rank IC、收益表现及最大回撤。
5. 检查新模型是否在多个窗口中表现稳定，避免仅根据单一测试窗口判断模型优劣。
6. 如果新模型通过评估，将模型记录至 MLflow，并根据评估结果人工更新模型 Alias。
7. 使用现有 FastAPI 推理接口验证模型加载和批量预测结果。

模型重新训练不代表模型自动上线。模型版本和 Alias 的调整应由人工完成，并保留相应评估记录。

### Phase 4：根因分析与后续改进

如果重新训练后模型预测效果仍未改善，应进一步排查：

1. 数据源质量及历史数据一致性。
2. Alpha158 特征在不同市场环境下的稳定性。
3. 训练窗口与当前市场分布之间的差异。
4. 模型参数、训练样本和验证方式是否存在问题。
5. 是否需要在后续版本中引入宏观经济或其他辅助特征。

涉及新增数据源、特征体系重构或监控能力扩展的工作，纳入后续版本规划，不作为当前版本的自动应急处置步骤。

## 4. 异常处置记录

每次异常处置建议记录以下信息：

- 异常发生日期及流水线运行 ID。
- 涉及的股票、数据文件或模型版本。
- 异常类型及监控指标。
- 根因分析结果。
- 已采取的处理措施。
- 是否重新训练模型及评估结果。
- 后续改进事项。

## 5. 通讯与告警

项目当前通过 Grafana Webhook 提供监控告警。

告警信息应至少包含：

- 告警类型及指标名称。
- 异常发生时间。
- 对应股票或特征名称。
- 当前指标值及告警阈值。
- 对应监控面板和排查日志位置。

后续如需接入钉钉、飞书等通知渠道，可在现有 Webhook 基础上扩展。
