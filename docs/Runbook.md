
# MLOps 量化选股实盘应急处置预案 (Runbook)

## 1. 触发条件
- **数据漂移（PSI）**：核心特征（如 `MAX60`, `CNTP60`）的 PSI 连续 2 个交易日 > 0.25，且触发 Webhook 告警。
- **模型失效（IC）**：实盘滚动 Rank IC 连续 5 个交易日 < 0。
- **宏观冲击**：如纳斯达克单日暴跌 > 4%（黑天鹅事件）。

## 2. 应急处置流程（SOP）

### Phase 1：人工确认与止损（T+0）
1. 收到告警后，立即登录 Grafana 查看“实盘每日真实 IC 趋势”与“PSI Top 10”。
2. 如果 PSI 爆表且 IC 转负，**立即通知交易员暂停实盘开仓**（或降低 50% 仓位）。
3. **严禁**在暴跌当日（黑天鹅）直接触发全自动重训，防止模型过拟合极端短期情绪。

### Phase 2：静默观察期（T+1 到 T+3）
1. 观察市场是否进入趋势性下跌（Regime Shift）。
2. 确认底层数据源（yfinance/券商 API）是否正常，排除数据源故障导致的假漂移。
3. 每日定时跑 `m5_run_daily_pipeline.sh` 以更新特征和监控面板，但**只监控，不重训**。

### Phase 3：增量重训与灰度验证（T+4 及以后）
若市场企稳或确认形成新的下跌趋势：
1. 修改 `m2_generate_walkforward.py`，增加新窗口（如 W10），将 Train 延伸到最新日期，Test 设置为最近的暴跌期。
2. 执行 `qrun` 跑出新模型，重点观察 **最大回撤（Max Drawdown）** 是否优于旧模型。
3. 将新模型注册为 `@candidate`，通过 FastAPI 影子模式（Shadow Mode）同时输出新旧模型打分。
4. 验证 3 天后，若 IC 稳定回升，在 MLflow 中将 `@candidate` 提拔为 `@production`，恢复实盘仓位。

### Phase 4：根因分析与因子淘汰
如果重训后新模型依然无法抵御暴跌（如回撤依旧超过 15%）：
1. 排查是否 Alpha158 因子集体失效（如当前市场转为由宏观利率主导，纯价量因子彻底失效）。
2. 启动二期计划：接入宏观因子（如 VIX、美债收益率）或另类数据因子，重构特征集。
